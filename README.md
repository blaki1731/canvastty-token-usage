# Token Usage — плагин для CanvasTTY

Плагин-приложение, которое показывает расход токенов по моделям для локальных
CLI-агентов. Есть две формы:

- **окно на рабочем столе CanvasTTY** — «Расход токенов», как терминал
  (двигается, растягивается, ресайзится горячими клавишами);
- **отдельное окно Electron** — «Расход токенов (окно)», то же приложение вне канваса
  (собственных возможностей плагина: ресайз, тема, фон).

В обеих:

- список приложений (CLI): Hermes, Codex, Claude Code, OpenCode — с выбором;
- период: 24 часа, 7 дней, 30 дней, всё время или произвольный диапазон дат;
- сводка: вход, выход, кэш (чтение), рассуждения, вызовы API, сессии;
- таблица по моделям с долей и график по дням;
- время до восстановления лимита токенов — по каждому приложению и по каждой модели;
- статус источников и их пути;
- изменение размера горячими клавишами: `Ctrl` + `+`/`-` (как в `resize`-плагине),
  `Ctrl` + стрелка, затем `+`/`-` — наращивает в ту сторону;
- переключатель фона окна: «Монохром», «Как в Canvas», «Полупрозрачный».

## Установка

1. Запустите `install.bat` (копирует плагин в `%APPDATA%\canvastty\plugins\token-usage`;
   реестр трогает только если плагин ещё не зарегистрирован).
2. Перезапустите CanvasTTY — реестр плагинов и манифест читаются при старте.
3. Если сервис не запускается: Настройки → Плагины → Token Usage → выключите и
   включите **native code** (сервису нужно читать локальные журналы агентов).
4. На карточке плагина откройте «Расход токенов» (окно на рабочем столе) и/или
   «Расход токенов (окно)» (отдельное окно Electron).

Удаление: `uninstall.bat` + перезапуск CanvasTTY.

> Репозиторий: https://github.com/blaki1731/canvastty-token-usage (приватный).
> Установить можно и из CanvasTTY: Настройки → Плагины → установка по URL репозитория.
> Для обновления — `install.bat`, затем перезапуск CanvasTTY.

> Карточка на канвасе открывается в sandboxed-iframe (`sandbox="allow-scripts"`,
> опаковый origin): её `localStorage` недоступен, но хранилище плагина работает —
> оно идёт через хост, а не через localStorage.

## Как это работает

- `app/` — окно плагина (HTML/CSS/JS), общается с хостом через `canvastty-plugin://host/sdk.js`.
- `services/usage.mjs` — сервис плагина (Node, `node:sqlite`), читает локальные данные и
  возвращает агрегат по моделям/дням. Запускается CanvasTTY как отдельный процесс,
  только когда включён native code плагина.

Источники:

| Приложение | Что читается |
|---|---|
| Hermes | `state.db` (таблицы `session_model_usage`, `sessions`) в `%HERMES_HOME%`, `%LOCALAPPDATA%\hermes`, `~/.hermes` и профилях |
| Codex | роллауты `~/.codex/sessions` и `archived_sessions` (или `CODEX_HOME`) — JSONL |
| Claude Code | транскрипты `~/.claude/projects`, `~/.config/claude/projects` (или `CLAUDE_CONFIG_DIR`) — JSONL |
| OpenCode | `opencode.db` (`session_v2`) в `~/.local/share/opencode`, `%LOCALAPPDATA%\opencode`, `OPENCODE_HOME` |

## Про точность

- Codex и Claude Code считаются по событиям журнала — каждый записанный расход попадает
  в свой день.
- Hermes и OpenCode хранят накопительные счётчики на сессию, поэтому токены сессии
  распределяются равномерно между первым и последним наблюдением (`first_seen`/`last_seen`
  или `time_created`/`time_updated`). Это оценка для длинных сессий; итог по модели и
  пересечение с диапазоном считаются по этой же равномерной разбивке.
- Всё читается только на этом компьютере: веб-чаты, десктопные приложения и другие
  профили ОС не учитываются.

## Восстановление лимитов

В списке приложений у каждой строки показано время до полного восстановления
лимита (например «лимит ~5 ч»), а в таблице моделей — колонка «Лимит» с тем же
временем для каждой модели. Наведение открывает подробности: точный момент
восстановления, когда окно начнёт освобождаться, недельное окно и расход в окне.

Важно: **ни один CLI-агент не пишет данные о лимитах в свои журналы** — проверено
для Hermes (`state.db`), OpenCode (`opencode.db`), Codex и Claude Code (JSONL).
Поэтому время считается оценочно, по скользящему окну: провайдер учитывает токены
запроса в течение окна от самого запроса, и окно освобождается полностью, когда
истекает самый свежий расход. Окно по умолчанию — 5 часов (плюс недельное,
оно в подсказке). Длину короткого окна можно передать параметром
`limitWindowMs` в `usage.query`.

## Оформление

Интерфейс повторяет тему CanvasTTY: сервис читает `%APPDATA%\canvastty\settings.json`
и выдаёт токены скина (`appSkin`) или палитры + цвет канвы (`canvasColor`) —
поверхности, акцент, рамка, тень, шрифт. Окно на рабочем столе получает рамку
от приложения; отдельное окно Electron рисует такую же рамку само (скругление
17px, рамка, тень).

Переключатель «Фон окна» (внизу сайдбара) выбирает режим фона:

- **Монохром** — сплошная поверхность темы;
- **Как в Canvas** — поверхность + точечный паттерн и оттенок цвета канвы;
- **Полупрозрачный** — полупрозрачная поверхность с `backdrop-filter: blur`.

Выбор запоминается в хранилище плагина.

## Горячие клавиши изменения размера

Поведение даёт вендоренная копия аддона `canvas-window-resize.js`
(отдельный репозиторий: <https://github.com/blaki1731/canvas-window-resize>,
каталог `addons/` в canvas-tty-plugins): он сам определяет контекст и работает
в обеих формах.

- в **окне на рабочем столе** клик выделяет карточку (аддон сообщает о клике
  хосту через `postMessage`), а `Ctrl`+`+`/`-` и `Ctrl`+стрелка затем `+`/`-`
  меняют размер карточки — как у терминалов;
- в **отдельном окне Electron** те же клавиши меняют размер самого окна
  (`window.resizeTo`/`moveTo`).

Лимиты и шаг — как у приложения: 1.15, 420×260 … 1600×1100, стрелка действует
1.2 с. Аддон независим от версии resize-плагина: его можно обновлять отдельно
и встраивать в новую версию набора.

## Разработка

1. Правьте файлы в `app/` или `services/usage.mjs`.
2. `install.bat` → перезапуск CanvasTTY → откройте карточку/окно плагина.
3. Изменение `services/usage.mjs` требует повторного включения native code
   (CanvasTTY привязывает доверие к SHA-256 входа сервиса): выключите и включите
   native code на карточке плагина, либо заново запишите `trustedServices`
   в `plugins.json` и перезапустите приложение.

## Известная проблема окружения (EPERM)

CanvasTTY при изменениях хуков Hermes атомарно перезаписывает
`%LOCALAPPDATA%\hermes\config.yaml`. Если этот файл держит другой процесс Hermes
(например, запущенный шлюз `hermes_cli.main gateway`), переименование падает с
`EPERM`, и часть IPC-вызовов (`plugins:set-native-code-trusted`,
`plugins:service-report`, `usage-history:get`) возвращает эту ошибку.
Обходной путь: остановить конкурирующий процесс Hermes либо предзаписать
`trustedServices` в `plugins.json` и перезапустить CanvasTTY. На работу самого
плагина это не влияет.

Проверить сервис отдельно можно так (JSON-RPC NDJSON по stdio):

```
echo {"jsonrpc":"2.0","id":1,"method":"usage.query","params":{"app":"hermes","from":0,"to":9999999999999}} | ^
  ELECTRON_RUN_AS_NODE=1 "C:\Program Files\CanvasTTY\CanvasTTY.exe" services\usage.mjs
```
